# 離線掛機 authoritative state

## Sponsor passes

`sponsor_passes` is the authority for `exp` / `gold` / `drop` / `offline`.
Each purchase uses `sponsor_pass_purchases.request_id` as its idempotency key,
locks the existing `account_wallets` row, and extends only the matching pass.
The legacy `offline_hunt_purchase_pass` RPC delegates to the unified purchase
RPC to preserve callers during the Edge Function transition.

The browser reads `sponsor.status` and purchases through
`sponsor.pass.purchase`; it must not use `player.sponsorPasses` for a
multiplier or permission decision.

## Immutable departure snapshot

`offline_hunt_departures.combat_snapshot` is generated by
`offline_hunt_build_snapshot()` during `offline_hunt_arm()`. It stores:

- character ID, level, class, map ID, catalog hash;
- offline / EXP / Gold / Drop pass expiry timestamps from `sponsor_passes`;
- active party count, online party reward multiplier and EXP bonus percentage;
- catalog-verified doll EXP/Gold fields and equipped relic drop-x2 effect;
- catalog-validated skill IDs and checkpoint-backed trial state.

The snapshot hash is persisted with the departure. Settlement must use only
this immutable value and split `[armed_at, min(now, offline pass expiry, 12h)]`
at each EXP, Gold and Drop pass expiry. A segment applies 1.2 only while that
pass is active; no later login, character switch, equipment change or renewal
may modify earlier segments.

## Dynamic-state classification

| State | Class | Offline policy |
| --- | --- | --- |
| World region / map identity | A | Catalog and immutable map snapshot. |
| World Tree skill, Refine Magic Stone skill | A | Validate skill ID from the checkpoint against catalog; apply only after settlement rules support it. |
| Area material rules | A | Derive solely from catalog map ID and validated skill snapshot. |
| Trial progress | B | Snapshot server-held checkpoint state; validate it against trial-rule catalog before granting a quest item. |
| EXP / Gold / Drop / Offline passes | A | `sponsor_passes`, split at expiry. |
| Doll and equipped relic effects | A | Equipment IDs from checkpoint, effects derived from catalog. |
| `_sherine`, `_grace` | B | Require a server-owned world-event/spawn instance ID. Never infer from mob ID. |
| Card drops | B | Require card tables and world/transform context in server catalog. |
| Siege / castle event | B | Require server-owned match state and reward ledger. |
| PVP / player NPC drops | C | Do not simulate offline; participant and alignment state are live-only. |
| Unidentified real-time events / transient mob flags | C until server-owned | Exclude rather than approximate. |

Cards, `_sherine`, `_grace`, siege rewards, PVP/player-NPC drops, random
equipment-affix outcomes and any live-only event whose state has no server
record are excluded from offline settlement until their B-state record exists.
